# Vibershot developer notes

Reference for working on the code: how the app behaves, where settings live and how to check changes by hand. The public overview is in the top-level [README](../README.md).

Windows desktop app using C# / .NET 10 / WPF. No browser, Electron, third-party packages, or C++ build is needed for the current screenshot flow. Capture calls the Windows GDI APIs directly; the process is idle between user actions.

## Run

Install the .NET 10 SDK (already present on this development machine), then run from this folder:

```powershell
.\run.ps1
```

Or build directly:

```powershell
dotnet build .\Vibershot.UI\Vibershot.UI.csproj -c Release
.\Vibershot.UI\bin\Release\net10.0-windows\Vibershot.exe
```

The rounded floating launcher can be moved by dragging its header. Its custom controls toggle always-on-top, minimize, and close the app. The glass-like surface uses translucency and static highlights without a continuous blur or capture loop. Click **Capture region**, then hover over a window or app content to see a glowing outline. Click to select the highlighted area, hold **Shift** for the whole window, or drag over the desktop for a manual region. Chromium render hosts and accessible document bounds identify browser pages without hardcoded toolbar heights; other apps fall back to their client area or visible window frame. Release to keep the selection highlighted while the unselected desktop is dimmed. The **Size** bar under the hint offers fixed frames instead: **720p**, **1080p**, **1440p**, **Square** (1080 × 1080) or **Custom** (type a width and height, remembered as `CustomRegionSize` in `config.json`). With one chosen, a frame of exactly that many screen pixels follows the pointer, a click places it, and a click elsewhere moves it; a video of it records at that size, so keep the windows you want inside the frame. **Free** returns to the usual hover, click and drag. Frames larger than the desktop are disabled. Choose **Save screenshot**, **Take video**, **Scrolling photo**, or **Cancel**. Drag again to replace the selection; **Esc** cancels. **Full desktop** captures the virtual desktop across monitors, including monitors to the left of the primary display. Closing the launcher hides it to the tray; Vibershot keeps running so hotkeys and Print Screen still work. Use the tray icon to show the launcher again or choose **Exit** to quit.

## Install and update

`tools\build-installer.ps1` publishes the app self-contained (no .NET install needed) with the bundled ffmpeg and compiles an Inno Setup installer, `VibershotSetup-<version>.exe`, plus a `latest.json` feed; `tools\publish-release.ps1` puts both on a GitHub release. The installer asks for per-user (default, no UAC) or all-users, the install folder, the **library folder**, and whether to start with Windows, associate `.vibeshot` files and add a desktop shortcut. Running a newer installer over an existing copy upgrades in place and keeps every previous choice. The app checks the latest release once a day (Settings → General, or **Check for updates…** in the tray menu), shows the notes, downloads the installer, verifies its SHA-256 and runs it silently; Vibershot closes, updates and reopens. Only one Vibershot runs per session: a second launch, including a double-clicked `.vibeshot` file, hands its arguments to the running copy. The full flow, the rehearsal procedure and the rules that keep updates working are in [RELEASING.md](RELEASING.md).

**First run.** A fresh install (no `config.json`) shows a welcome page: where the library lives (default `Pictures\Screenshots\Vibershot Gallery`, next to the Windows Screenshots folder, falling back to `%APPDATA%\Vibershot` when Pictures cannot be resolved), whether Vibershot should handle **Print Screen** (on by default) and whether to start with Windows. When the installer already asked about the library and startup (it leaves `%APPDATA%\Vibershot\install-choices.json`, which the first launch folds into a fresh config and deletes), the page only asks about Print Screen. The page is skipped for existing configs, and a tray launch at sign-in defers it until the launcher is shown or a capture is made.

**Hotkeys** (Settings → Hotkeys). **Print Screen** takeover is on by default and either opens the region tool (then asks what to capture, or takes a screenshot right away) or snaps the full desktop. If Windows still routes the key to Snipping Tool the registration fails, the launcher footer says so, and the settings page links to the Windows setting (**Use the Print screen key to open screen capture**) to turn off. Five actions can have their own global shortcut, recorded by pressing the keys: capture region or window (default **Ctrl+Shift+S**), full desktop, record video (opens the region tool and starts a recording after the selection), open gallery and open editor. Shortcuts are stored as text under `Hotkeys` in `config.json` (`"Ctrl+Alt+F9"`); a letter or digit needs at least one modifier, function keys and Print Screen stand alone. Conflicts between actions and combinations taken by another app are reported inline. **Start with Windows** (Settings → General) adds a per-user Run entry that launches Vibershot straight into the tray (`Vibershot.exe --tray`) at sign-in; the entry is refreshed on each start so it follows a moved executable.

**After a screenshot** (Settings → After capture). Four independent switches run in order, and any mix is allowed; with everything off the capture is not kept and only shows in the small preview. **Save as file** writes the capture to every checked destination: the **Library** (its `Screenshots` folder) and any number of custom folders, each getting its own copy and a gallery sidecar; or **Ask for a name and folder each time** shows a Save As dialog instead. The format defaults to the editable **Vibershot project** (`.vibeshot`, full-quality pixels plus layers; see Editor) and can be PNG, JPEG, WebP lossless or WebP with a 1–100% quality slider (WebP encoding uses SkiaSharp since WPF has no in-box encoder). **Copy to clipboard** puts the picture on the clipboard. **Open in gallery** shows the new file selected in the library (it needs the library copy, so it keeps that destination checked). **Open in editor** opens the capture on a new canvas; when a project was saved it opens that file so Ctrl+S writes back to it. When neither window opens, **Show the small preview** (on by default) shows the capture with **Copy image**, **Save as…** (every format including the project) and **Edit**. Presets (Quick copy, Save to library, Save and edit, Save and review) set the four switches in one click, and a summary strip reads the current setup back as a sentence. These live under `AfterCapture` in `config.json`; configs written before this layout (flat `OutputFolder`, `Autosave`, `ShowSaveDialog`, `CopyToClipboard`, `Format`, `WebpQuality`, `HotkeyDescription`, `Gallery.OpenGalleryAfterCapture`, `Editor.OpenEditorAfterCapture`) are folded into the sections on first load and never written back: a custom output folder becomes a checked destination and a watched gallery folder, the old `%APPDATA%\Vibershot` library root is kept, the chosen flat image format is kept, and the welcome page is skipped.

## Editor

**Edit** on the preview (the primary button there) opens the capture in the image editor; the launcher's **Editor** tile opens whatever image is on the clipboard, or asks for the size of a new canvas. Setting `Editor.OpenEditorAfterCapture` to `true` in `config.json` skips the preview and opens the editor after every screenshot.

The editor is a layered vector document: the capture is an image item on a base layer, annotations go on a layer above, and nothing is baked until export. The canvas under every layer is white by default; Settings → Editor → **Canvas background** picks white, black, transparent (the checkerboard shows through and exports keep their alpha) or a custom colour for new documents, and the **Canvas** strip in the editor's Picture panel changes it per document. Tools sit in an icon grid at the top of the left column, with keyboard letters: **Select** (V), **Marquee** (M), **Crop** (C), **Arrow** (A), **Shape** (S; press again to cycle rectangle, ellipse and line, or open the flyout), **Text** (T), **Callout** (O), **Stamp** (K), **Blur** (B) and **Image** (I, places an image file). Drag to draw; Shift constrains to squares and 45° angles. Click selects, Shift-click adds, dragging on empty space selects every item the box touches; the selected item shows eight resize handles and a rotate handle; arrow keys nudge by 1 px (Shift: 10 px); Delete removes; Ctrl+A selects all; the context menu moves items forward and back. Double-click a text item (or finish creating one) to type in place; the properties panel on the right edits stroke, fill, width, opacity, corner radius, arrow head size, drop shadow, and for text the font family, size, bold/italic/underline, colour, alignment, background and padding. Ctrl+wheel zooms around the pointer, **Fit** and **1:1** set the view, and Space-drag or the middle button pans. **Ctrl+0** is actual size: one picture pixel per display pixel, also on a scaled display (the zoom readout is relative to that). Fit to window has no shortcut by default; both are set under Settings → Editor → **View shortcuts** (`Editor.ActualSizeShortcut`, `Editor.FitShortcut`).

The left column under the tool grid is the **tool panel**. It names the active tool and groups its settings: **Style** (which shape or callout), **Colour** (stroke, fill, text and background together), **Line** (width, corner radius, arrow head), **Text** and **Effects** (opacity, drop shadow). With a drawing tool active (Arrow, Shape, Text, Callout) the panel edits the style of the *next* item, labelled "New arrow" and so on, and the item just drawn follows along; with the Select tool it edits the selection, and a change there carries on to the next item of that kind. With nothing selected the Select tool shows the picture's own settings (canvas size, image size, canvas colour).

The right sidebar holds the **Library** and the **Layers**. The library has four tabs (Arrows, Shapes, Callouts, Stamps) of ready-made presets, each drawn as a live preview; click one to insert it in the middle of the view, or drag it onto the picture. An inserted preset also becomes the style its tool draws next. The **theme** button above the tabs picks the look every preset and every drawing tool starts from: its colours, line width and corner radii. **Default** follows Settings → Editor's stroke colour and width; Vibershot, Signal red, Blueprint and Marker are built in. Choosing a theme never restyles items already on the picture. Themes and presets live in `Vibershot.Editing/StyleLibrary.cs`: a new theme is one `StyleTheme` entry and a new preset one line in `Presets`. The chevron beside "Library" (or View → **Collapse sidebar**) folds the sidebar to a strip; the choice and the theme are remembered in `config.json` (`Editor.SidebarCollapsed`, `Editor.Theme`).

Every slider in the properties panel has a number box beside it. The slider covers the everyday range; the box takes any value (stroke width to 1000 px, arrow head to 2000 px, corner radius to 5000 px, font size to 2000 px), so a 4K picture can have a 100 px line. Enter commits, Esc reverts, Up and Down step by one (ten with Shift). **Head roundness** on an arrow runs from a sharp point (0%) to a fully rounded head (100%); the head stays on the point it aims at.

**Callouts** are text boxes with a body and pointers, in four styles: **Label** (a box whose pointers are arrows), **Speech** and **Oval** (bubbles with tails) and **Thought** (a cloud with a trail of bubbles). Drag from the thing being pointed at to where the callout should sit, then type; a click places one without dragging. A selected callout shows a round handle on each pointer tip; **Add arrow** / **Remove arrow** change how many it has, and its panel edits the outline, background, text, corner radius, arrow head size and roundness. Moving a callout moves its pointers with it; hold **Alt** while dragging to leave them aimed where they were. Press O again to step through the styles.

**Stamps** are ready-made vector symbols (smiley, house, mouse pointers, tick, cross, star, warning and so on). Pick one from the searchable grid, then click to place it or drag to size it (Shift stretches). Fill sets its main colour and Stroke its line colour. They are path data on a 24 × 24 grid in `Vibershot.Editing/StampLibrary.cs`: a new stamp is one entry there.

**Blur** hides what should not be readable. Paint with the **Brush** or drag a **Box**, as **Blur** or **Pixelate**, with a strength and a brush size; the Marquee tool has the same choice and a **Blur selection** button for the selected pixels. Each pass flattens the active layer and everything under it, obscures that copy and places it as a new image item over the same spot, so the hidden pixels are really gone from an export (there is no effect to remove), and the patch can be moved, deleted or undone.

**New canvas…** (Ctrl+N; the launcher's Editor tile shows it when the clipboard has no image) asks for a size, with 720p, 1080p, 1440p, 4K, square, portrait and banner presets, and a background. **Canvas size…** (Image menu, or the Picture panel) adds or trims space on any side: type a new size and choose which part of the picture stays put, or type the pixels for each side (negative trims); nothing is scaled or deleted, and **Trim to crop** makes the crop permanent. **Image size…** scales the whole document, keeping proportions unless unticked: positions, stroke widths, fonts and corner radii all follow, and bitmaps are drawn from their original pixels. A canvas is limited to 30,000 px a side and 120 megapixels.

**Crop** draws a rectangle with handles; Enter (or **Apply crop**) keeps it as a non-destructive crop and **Reset crop** brings everything back. **Marquee** selects pixels: drag inside the box or press V to lift them into a floating image item that moves, resizes and deletes like any other item (the picture underneath is cleared to the canvas colour), Ctrl+C copies the region as a flat image, Ctrl+X copies and clears it, and Delete clears it. Lifting and clearing only touch image items on visible, unlocked layers and skip rotated images; every image edit swaps in a fresh asset so undo restores the original pixels. Copy, Cut and Paste work on items (Ctrl+C/X/V, Ctrl+D duplicates): items travel as JSON under the private `Vibershot.Items` clipboard format next to a flattened PNG, so they paste into the editor as editable items and into other apps as a picture; an image on the system clipboard pastes as an image item centred in view (images inside images), text pastes as a text box, and image files dropped on the canvas become image items. Undo and redo (Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z) treat each drag as one step.

The **Layers** panel lists layers top to bottom with an eye (visibility), a padlock (locked layers cannot be selected or edited) and an item count. Click a row to make it the active layer, where new items, pastes, duplicates and placed images land; selecting an item activates its layer. Double-click renames; the row's context menu offers **Rename**, **Move selection here**, **Merge down** and **Delete layer**; the header buttons add a layer above the active one, move it up or down, or delete it (the last layer stays), and the **Layer opacity** slider fades the whole layer. Hidden and locked layers drop out of the selection, and every layer change is one undo step.

The project format is the default for both captures and the editor. **Save project** (Ctrl+S; **Save project as…** Ctrl+Shift+S) writes a `.vibeshot` file (a zip with `document.json`, the embedded full-quality PNG assets and a `preview.png` for galleries) into the library's `Projects` folder, or back to the capture's own file when it was saved as a project. It reopens with every item still editable via **Open…** (Ctrl+O; also accepts png, jpg, webp, gif, bmp and tif), by dropping it on the canvas, from the gallery, or with `Vibershot.exe --edit <file>`. **Export image…** (Ctrl+E) opens a dialog with the format (PNG, JPEG, WebP lossy, WebP lossless), a quality slider for the lossy ones, the pixel size and the real encoded size, and a preview that shows the decoded result so compression artefacts are visible before writing. An export is flat: after exporting a document that has no project file or unsaved changes, a notice bar explains that text, shapes and layers in the export cannot be edited again and offers **Save project**; closing such a window asks the same question in the save prompt. The document JSON carries a `version` (currently 1), the canvas size, crop and background colour, and the layers with their name, visibility, lock, opacity and items; each item has a `type` discriminator (`image`, `rect`, `ellipse`, `line`, `arrow`, `text`, `callout`, `stamp`) and its own properties, and image items point at a PNG under `assets/` by id, so text stays text and layers stay layers after a round trip; **Export…** (Ctrl+E) flattens to PNG, JPEG or WebP through the same encoder as the preview, honouring the crop and rendering tall canvases in 4096 px bands; **Copy image** puts the flattened picture on the clipboard. Closing with unsaved edits asks to save, discard or cancel. Defaults for new items live under `Editor` in `config.json` (`DefaultFontFamily`, `DefaultFontSize`, `DefaultStrokeColor`, `DefaultStrokeWidth`).

## Gallery

Every capture saved to the library lands in the gallery and stays until deleted. Open it from the launcher's **Gallery** row, the tray menu or its hotkey. The **library** is the folder Vibershot owns (`Pictures\Screenshots\Vibershot Gallery` by default, chosen on first run, movable from Settings → Gallery) with `Screenshots`, `Recordings` and `Projects` under it. The gallery scans those three folders, `%LOCALAPPDATA%\Vibershot\Recordings` (recovery copies of recordings) and the folders listed under **Also watch** (`Gallery.ExtraFolders` in `config.json`), recursively and with no database. Custom save destinations are deliberately not watched, so a capture written to the library and to a custom folder shows once; add the folder under Also watch to see it. Images (png, jpg, webp, gif, bmp), videos (avi, mp4, mkv, webm, mov) and `.vibeshot` / `.vibevideo` projects are shown; a `FileSystemWatcher` picks up new files within a second and every activation of the window rescans, so nothing needs a restart. The Save As for a finished recording starts in the library's `Recordings` folder.

**Clean up old items** (Settings → Gallery, off by default) moves library files older than a chosen number of days to the Recycle Bin, with separate switches and day counts for screenshots (30), recordings (14) and unsaved recording recovery files (7). It only ever touches the library's `Screenshots` and `Recordings` folders and the recovery folder, never watched folders, custom save destinations, subfolders or projects; age comes from the sidecar's capture time, else the file's creation time; a pass runs at startup at most once a day and reports what it moved in the launcher footer.

Each save writes a sidecar `<file>.vibe.json` next to the capture: the capture kind (region, window, full desktop, scrolling, video), the source app and window title when the selection was made over a window, pixel size, duration for videos, capture time, tags and the favourite flag. Files without a sidecar still show up with what the file system knows. Deleting a sidecar loses only that metadata; everything stays readable in Explorer. Thumbnails are 320 px JPEGs cached under `%LOCALAPPDATA%\Vibershot\Thumbs` keyed by path, size and modification time; large stitched images are decoded at reduced size rather than loaded fully. `.vibeshot` tiles come from the `preview.png` embedded in the project (projects saved before previews existed get a neutral tile). Video tiles use the Windows shell thumbnail when one exists, otherwise a frame decoded by the bundled ffmpeg (`FfmpegVideoThumbnailer`), and a neutral film tile when neither can read the file.

The window has a rail with **All / Images / Videos / Projects / Favourites** and a tag list, a search box over file names, apps, window titles and tags (Ctrl+F), sort by date, name or size, and a tile size slider. Tiles are grouped by day and show the kind, dimensions or duration, and a favourite star. Select with click, Ctrl/Shift, or by dragging a marquee over empty space; arrow keys move, **Enter** opens, **F2** renames in place, **Space** toggles favourite, **T** opens the tag flyout, **Ctrl+C** copies the file, **Ctrl+Shift+C** copies the image, **Delete** moves to the Recycle Bin (sidecar and thumbnail go too). The toolbar and context menu offer the same plus **Show in folder** and **Open original**. Drag tiles out to drop files on other apps; drop files in to copy them into the save location with an "Imported" sidecar. The **Details** pane shows a large preview, metadata and a tag editor. **Capture region** in the header starts a capture, so the gallery can stay open as a home base; Settings → Gallery → **Open the gallery after each capture** then shows the new capture selected instead of the preview. The gutters either side of the tiles are splitters: drag one to resize the rail (150 to 380 px) or the detail pane (260 to 1100 px), and double-click it to reset. The preview in the detail pane grows with the pane, so a wide pane gives a large look at the capture. Window placement, tile size, both widths and the detail pane state are remembered.

Images and `.vibeshot` projects open in the image editor; MP4s and `.vibevideo` projects open in the video editor (`GalleryWindow.OpenInEditor` / `OpenInVideoEditor`). Other video formats open with the default Windows app, like **Open original**.

## Video editor

`VideoEditorWindow` opens from the gallery (an MP4 or a `.vibevideo` project), from `--edit <file>`, or empty from another editor window. It cuts, layers and exports video, places videos and still pictures over one another on screen, shows waveforms on the audio lanes, and adds text, callouts, shapes, arrows, stamps and captions (with SRT import and export) on top.

- **Project** (`Vibershot.Editing/Video`): an immutable `VideoProject` (canvas size, frame rate, linked `MediaSource`s, tracks) on the same `History<T>` as the image editor. Visual tracks are listed bottom layer first. Clip start and length are whole frames at the project rate; `SourceIn` is seconds into the file. A video and its sound share a `LinkId` and move, trim and split together until detached. Every edit is a pure function in `TimelineOps`.
- **Placement**: a `VideoClip` or `ImageClip` (both `VisualClip`) may carry a `Placement`: the box on the canvas its visible part is stretched into, a rotation about the box's centre, an opacity and a crop as fractions of the source. Without one the clip is fitted inside the canvas and centred (`TimelineOps.PlacementOf`). Stills (PNG, JPEG, BMP, WebP) are `MediaSource`s with `IsImage`; their clips start at five seconds and their own size, and can be any length.
- **Graphics**: a `GraphicClip` wraps one of the image editor's `Item` records (text, callout, rectangle, ellipse, arrow, line, stamp) with its bounds in canvas pixels, sits on a visual track and layers with the pictures there. The Elements tab (`VideoElements`) lists the image editor's `StyleLibrary` presets, designed for 720 lines and scaled to the canvas when dropped on the picture or the timeline. `DocumentRenderer.RenderItem` draws them in the preview and for the export, so the two match.
- **Captions**: a caption track (`TrackKind.Caption`, drawn over everything) holds `CaptionClip`s; the track's `CaptionStyle` (font size, colours, top or bottom) applies to all of them, and `TimelineOps.CaptionItem` turns one into the text box that is drawn. `Srt` reads and writes SubRip files (File → Import / Export captions).
- **Project file**: `.vibevideo` is plain JSON that links to its media by absolute path and by path relative to the project, so a folder holding both can move. Missing files are asked for on open. Media is never copied.
- **Preview** (`VideoPreview`): one ffmpeg `FrameReader` per visible layer writes BGRA frames into a `WriteableBitmap`; layers that are fully covered are not decoded, and late frames are dropped. Stills are decoded once by WPF. The selected picture carries handles: drag it to move (it snaps to the canvas edges and centre), a handle to resize (corners keep the shape unless Shift is held), the knob above it to turn, and in crop mode (the **Crop** button, or a double-click) the handles cut its edges away. The handle maths lives in `HandleMath`, shared with the image editor. Like the timeline, the mouse handlers forward to public `PointerDown` / `PointerMove` / `PointerUp`. A `Stopwatch` drives playback. Sound is the timeline's audio mixed by ffmpeg into a cached WAV (`ExportArguments.BuildAudioMix`) and played with `MediaPlayer`.
- **Preview quality** (`AppConfig.VideoEditor`): Auto, Full, Half or Quarter, plus "use proxies" and "decode on the GPU". `ProxyCache` builds one 720-line proxy per source with a 15-frame GOP under `%LOCALAPPDATA%\Vibershot\Proxies`; on the 4K60 test clip a seek took about 76 ms on the proxy against 350 to 575 ms on the original, which is why proxies are on by default. GPU decode is off by default because copying frames back was slower than decoding on the CPU.
- **Timeline** (`TimelineView`): drawn in `OnRender`. The mouse handlers forward to `PointerDown` / `PointerMove` / `PointerUp`, which the test program calls directly, so drags, trims, layer changes and razor cuts are tested without a real pointer. The selection is a set with one primary clip (the one the properties panel shows): Ctrl+click toggles, Shift+click adds the run from the primary clip on that track, a drag on empty lane draws a marquee, Ctrl+A selects all and Esc none. Dragging a selected clip moves the whole set by the same frames, and the clips of its kind by the same lanes (`TimelineOps.MoveMany`); a move that would overlap a clip outside the set snaps back. Delete, ripple delete, copy, cut, paste at the playhead and duplicate (Ctrl+C / X / V / D) act on the set; the clipboard is `TimelineView.Clipboard`, inside the app only, and a paste with no room on the original track makes a new track of that kind. Audio clips draw a waveform from `WaveformCache` (mono 8 kHz peaks read once with ffmpeg and kept under `%LOCALAPPDATA%\Vibershot\Waveforms`).
- **Looking at the window while Vibershot is running**: a second `Vibershot.exe` hands its arguments to the running copy and exits, and a build fails while the running copy locks `bin\Release`. Build Debug and run `tests\CaptureChecks\bin\Debug\net10.0-windows\CaptureChecks.exe --editor <file> [action…]`: it opens the video editor on its own (`App.Hosted` skips the single-instance hand-off, tray and hotkeys) and then runs the actions in turn: `pick:x,y` clicks the preview at a canvas point, `element:Shapes:outline@x,y` adds a palette element, `caption` adds a caption, `elements` shows the Elements tab, `edit` starts typing in place on the selected text.
- **Export** (`ExportArguments.Build`): one `filter_complex` that crops each picture, scales it into its box, fades and turns it, shifts it to its timeline position and overlays it for exactly its own frames, in layer order, then mixes the audio. `TimelineOps.ToPlan` scales the boxes when the export size differs from the canvas. Given a folder, it also has `GraphicExport` draw each graphic into a transparent PNG (overlaid like a still for its clip) and each caption track into one run of same-sized PNGs listed in an ffconcat file, so any number of captions is one ffmpeg input. Each list entry carries `option framerate <project rate>`: left at the image reader's default 25 fps, caption times are rounded to 1/25 s and land a frame late at 30 or 60 fps. It always reads the original files. The encoder comes from `EncoderProbe`.

## Layout and next steps
- `Vibershot.UI`: floating launcher, hotkey, region overlay, preview, editor, gallery, settings, tray.
- `Vibershot.Core`: one-shot screen capture, clipboard, image encoding, settings.
- `Vibershot.Editing`: the editor's document model, history, renderer, project file and item clipboard (no windows, so the console checks can test it).
- `Vibershot.Gallery`: capture sidecars, library index and watcher, search/filter/sort, thumbnail cache, Recycle Bin and file operations (no windows).
- `Vibershot.Media`: ffmpeg process runner, ffprobe, encoder probe, recording argument builders and the MP4 recorder session (no WPF windows).
- `Vibershot.Engine`: original C++ stub, retained but not built or loaded by this version.

Working now: region and full-desktop screenshots, compact launcher, dimmed region action chooser, preview, image editor with arrows, shapes, text, placed images, crop and projects, a gallery of every capture with search and tags, PNG/JPEG/WebP output, clipboard, persisted settings, MP4 region video at a chosen frame rate with pause/resume, and manually advanced scrolling/stitching. `tests\CaptureChecks` is a plain console program; it runs the live ffmpeg checks when `tools\ffmpeg` is present and skips them otherwise.

**Video:** **Take video** records the selected region as an H.264 MP4 through the bundled FFmpeg (see below). Settings → Video picks the format (MP4, or the legacy AVI), the frame rate (24 / 25 / 29.97 / 30 / 50 / 59.94 / 60, stored as an exact rational such as `30000/1001`), a 1–100 quality slider mapped to the encoder's CRF/CQ, whether to prefer a hardware encoder (NVIDIA NVENC, Intel Quick Sync, AMD AMF; software `libx264`, Media Foundation or OpenH264 otherwise; probed once per session with a one-second null encode) and whether to draw the cursor. Capture uses Desktop Duplication (`ddagrab`) on the monitor containing the region and drops to GDI `gdigrab` when it produces no frames within three seconds; the session panel shows the real fps, elapsed time, frame count, file size, encoder and grabber. While recording, a click-through tangerine outline marks the recorded region (dimmed while paused); it is drawn just outside the region and excluded from capture, so it never appears in the video. While recording, ffmpeg writes a fragmented MP4 under `%LOCALAPPDATA%\Vibershot\Recordings` so a crash still leaves a playable file; **Pause** ends a segment and **Resume** starts another; **Stop & save…** joins the segments (stream copy) into a normal faststart MP4 and offers a Save As (Cancel keeps the recovery copy). There is no audio yet. If ffmpeg is missing or both grabbers fail, the session falls back to the original GDI Motion JPEG AVI recorder at 10 fps and says so in its status line; that recorder stops at 1.8 GB. Windows capture exclusion keeps session controls out of captures on supported Windows versions; keep controls outside the region on older systems.

## FFmpeg

MP4 recording runs `ffmpeg.exe` as a child process; nothing links against its libraries. The binaries are not in the repository: `tools\get-ffmpeg.ps1` downloads the current `ffmpeg-master-latest-win64-lgpl` build from [BtbN/FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds/releases) (GPL only if the LGPL asset is unavailable) into `tools\ffmpeg\` (`ffmpeg.exe`, `ffprobe.exe`, `LICENSE`, `SOURCE.txt`), which is git-ignored. `run.ps1` calls the script when `ffmpeg.exe` is absent, and `Vibershot.UI.csproj` copies the folder to `ffmpeg\` next to the executable. At run time `FfmpegLocator` looks in that output folder, then `tools\ffmpeg` above the executable for development builds, then `PATH`; the launcher footer reports a missing or broken binary at startup. The LGPL build has no `libx264`; it uses the GPU encoders, Media Foundation or OpenH264 instead. Keep `tools\ffmpeg\LICENSE` with any redistributed copy: the LGPL build must be shipped as separate, replaceable executables, which is how Vibershot uses it.

**Scrolling photo:** the initial region becomes the first shot. Scroll the browser down by less than a viewport, click **Add shot**, and return to the browser during the two-second delay. Keep at least 20% overlap, exclude sticky browser/page headers, and avoid moving content. The app aligns each shot vertically and appends the new content. Finish opens the usual photo save/preview flow; Cancel discards the session. This is a manually advanced browser stitcher, not automated full-page browser capture. Images are limited to 80 megapixels.

GDI is appropriate for still captures; video uses DXGI Desktop Duplication and hardware encoding through ffmpeg. ## Manual smoke checks

1. Start the launcher; capture a region and verify preview dimensions match the selected area.
2. Check that the launcher and selection border are absent in the output.
3. Paste the copied image into an image-capable application; check the autosaved PNG.
4. Capture the full desktop; test a monitor with negative coordinates if available.
5. Press Esc during selection; the launcher should return without creating a capture.
6. Disable the action chooser and autosave/clipboard in Settings; capture and save manually from the preview. Test Save As enabled/disabled independently, including cancelling the dialog.
7. Check Ctrl+Shift+S from another app; if occupied, the launcher reports the conflict.

Protected video surfaces and secure desktops are outside the current capture scope. Mixed-DPI monitor layouts should receive additional testing on real hardware.

8. Select a region and cancel using the chooser; verify no screenshot is saved. Redraw the region and check dimming follows the new selection.
9. Record a short MP4 with Pause and Resume; the status line should show the encoder, grabber, fps and size. Stop & save and play it in Windows Media Player and VLC; the frame rate must match Settings → Video. Switch the format to AVI, record again and play it in an AVI-capable player. Cancel a Save As; the recovery copy under `%LOCALAPPDATA%\Vibershot\Recordings` must remain.
10. Stitch overlapping browser shots, then test unchanged content and an excessive scroll; alignment failures should keep the previous image intact.

11. Hover over a Chrome/Edge page: verify the outline excludes tabs and address bar. Hold Shift to select the visible window frame. Click and test screenshot/video/scrolling actions. Test another app, overlapping windows, maximized windows, negative monitor coordinates, and mixed DPI. Drag to override an unsuitable automatic area. Window/content capture records a fixed visible desktop rectangle; it does not follow moved windows or capture through occluding windows.
12. Enable **Take over Print Screen** in Settings; press Print Screen from another app with each mode. Disable it and confirm Windows handles the key again without restarting.
13. Capture a region and click **Edit**. Draw an arrow (A), add a text box (T) and type, copy an image elsewhere and Ctrl+V it into the picture, crop (C, drag, Enter), then undo three times and redo. Export a PNG and check it matches the canvas and the crop. Save the project, close, reopen it with **Open…** and confirm every item is still selectable and editable; close with unsaved edits and check the Save / Discard / Cancel prompt.
14. Run `tests/CaptureChecks` (`dotnet build tests/CaptureChecks/CaptureChecks.csproj -c Release` then the built exe); it must print `PASS`, covering history undo/redo/coalescing, document operations, project round trips, JSON polymorphism, banded flattening, version ordering, the update feed, local download with checksum and the installer seed.
15. Capture a window by clicking it in the overlay, then open **Gallery**: the tile appears under TODAY without a restart and its `.vibe.json` names the app and window title. Search for the app name; only matching tiles stay. Copy a PNG into the save folder by hand and watch the tile appear.
16. In the gallery: press **F2** to rename (the sidecar is renamed too), click the star and add a tag (both show in the rail and survive a restart), drag a marquee over empty space to select several tiles, drag a tile onto the desktop (a copy appears), drop an image onto the window (it is imported into the save folder), and press **Delete**: the file lands in the Recycle Bin and the tile disappears. Turn on **Open the gallery after each capture** and capture again; the gallery opens with the new tile selected.
17. In the editor, press M and drag over part of the picture, then press V: the region becomes a selected floating image and the hole underneath shows the canvas colour. Drag it, undo, and repeat by dragging inside the marquee instead of pressing V. Marquee again, press Ctrl+X and paste elsewhere; marquee once more and press Delete. Add a layer, rename it by double-click, draw a shape on it, hide the layer (the shape and its selection vanish), lock it, and use the row's context menu to merge it down. Set Settings → Editor → **Canvas background** to Transparent, open a new editor and check the checkerboard shows through an exported PNG's cleared area; then pick a colour in the Picture panel's **Canvas** strip and confirm it survives save and reopen.
18. Build the installer (`tools\build-installer.ps1`), install it silently into a test folder with `/LIBRARY=`, launch: the welcome page asks only about Print Screen and the config carries the chosen library. Launch a second copy: it exits and the first shows the launcher. Point `Updates.FeedUrl` at a local `latest.json` with a higher version (docs/RELEASING.md): the update dialog appears, **Install and restart** closes the app, reinstalls and relaunches with "Updated to Vibershot …" in the footer. Uninstall: the library and config stay, the Run key goes.
